# Railflag OpenFeature provider for Go

Railflag's OpenFeature provider for Go 1.26+. It downloads your environment's flag config once,
evaluates every flag check in process (under a microsecond, no network call), and picks up changes
within a second over Server-Sent Events. If the stream drops it polls every 30 s, and if Railflag
can't be reached it keeps serving the last config it had. The only dependency is the OpenFeature Go SDK.

```sh
go get railflag.com/go/openfeature
```

```go
import (
	"github.com/open-feature/go-sdk/openfeature"
	railflag "railflag.com/go/openfeature"
)

provider, err := railflag.NewProvider(railflag.Options{
	SDKKey:  os.Getenv("RAILFLAG_SERVER_KEY"), // a server key: Environments → keys
	BaseURL: "https://relay.railflag.com",      // required: your Railflag relay
})
if err != nil {
	log.Fatal(err)
}
if err := openfeature.SetProviderAndWait(provider); err != nil {
	log.Fatal(err)
}
client := openfeature.NewDefaultClient()

on, _ := client.BooleanValue(ctx, "new-checkout", false,
	openfeature.NewEvaluationContext("user-42", map[string]any{"plan": "pro", "country": "GR"}))
```

- `BooleanValue`, `StringValue`, `IntValue`, `FloatValue` and `ObjectValue` (and their `…Details`) work as in any OpenFeature provider. A wrong type or unknown flag returns your default with an error code. `IntValue` on a number flag that isn't a whole number is a type mismatch.
- `ObjectValue` returns `map[string]any` or `[]any`, with numbers as `float64`.
- Context values can be any Go numbers, strings, bools, slices and string-keyed maps. `time.Time` values are compared as instants, so `before`/`after` rules work with them.
- `openfeature.AddHandler(openfeature.ProviderConfigChange, &fn)` tells you when flags change; `details.FlagChanges` lists them.
- Call `openfeature.Shutdown()` on exit to close the stream.
- Server keys can read every rule. Keep them on the server; browsers use the JavaScript SDK with a client key.
- Once a minute the provider sends how many times each flag returned each variation, for [Release Watch](https://railflag.com/release-watch). It sends counts only, such as `{"new-checkout": {"1": 42}}`, and never contexts or user ids. Sending runs on a background goroutine and never delays a flag check. `openfeature.Shutdown()` sends what's left. Turn it off with `DisableExposures: true`.

## Same answers as every other SDK

`evaluate.go` is a port of `packages/eval`, Railflag's TypeScript evaluator. The tests run it against
the shared test vectors (hashes, buckets and thousands of evaluations generated by the TypeScript
evaluator), so a user lands in the same variation whichever SDK evaluates the flag. Context values
follow JavaScript rules: `1` and `true` are different, numbers print as JavaScript prints them, and
strings sort by UTF-16 code units.

Known differences: regexes in `matches` rules run on Go's RE2, so a pattern with lookaround or
backreferences doesn't match anything, and a date-time without a time zone is read as UTC.

## Development

The source lives in the Railflag monorepo (`packages/sdk-go`); the public module is a mirror of it.

```sh
go test -race ./...   # in the monorepo, also runs the shared evaluation vectors
```
