# Railflag OpenFeature provider for Java and Kotlin

Railflag's OpenFeature provider for the JVM (Java 11+). It downloads your environment's flag config once,
evaluates every flag check in process (a few microseconds, no network call), and picks up changes within
a second over Server-Sent Events. If the stream drops it polls every 30 s, and if Railflag can't be
reached it keeps serving the last config it had. The only dependency is the OpenFeature Java SDK.

```kotlin
// build.gradle.kts
implementation("com.railflag:railflag-openfeature:0.2.0")
```

```xml
<!-- pom.xml -->
<dependency>
  <groupId>com.railflag</groupId>
  <artifactId>railflag-openfeature</artifactId>
  <version>0.2.0</version>
</dependency>
```

## Java

```java
import com.railflag.openfeature.RailflagOptions;
import com.railflag.openfeature.RailflagProvider;
import dev.openfeature.sdk.*;

OpenFeatureAPI api = OpenFeatureAPI.getInstance();
api.setProviderAndWait(new RailflagProvider(RailflagOptions.builder()
    .sdkKey(System.getenv("RAILFLAG_SERVER_KEY")) // a server key: Environments → keys
    .baseUrl("https://relay.railflag.com")        // required: your Railflag relay
    .build()));
Client client = api.getClient();

boolean on = client.getBooleanValue("new-checkout", false,
    new ImmutableContext("user-42", Map.of("plan", new Value("pro"), "country", new Value("GR"))));
```

## Kotlin

```kotlin
import com.railflag.openfeature.RailflagOptions
import com.railflag.openfeature.RailflagProvider
import dev.openfeature.sdk.*

val api = OpenFeatureAPI.getInstance()
api.setProviderAndWait(RailflagProvider(RailflagOptions.builder()
    .sdkKey(System.getenv("RAILFLAG_SERVER_KEY"))
    .baseUrl("https://relay.railflag.com")
    .build()))
val client = api.client

val on = client.getBooleanValue("new-checkout", false,
    ImmutableContext("user-42", mapOf("plan" to Value("pro"), "country" to Value("GR"))))
```

- `getBooleanValue`, `getStringValue`, `getIntegerValue`, `getLongValue`, `getDoubleValue` and `getObjectValue` (and their `…Details`) work as in any OpenFeature provider. A wrong type or unknown flag returns your default with an error code. `getIntegerValue` or `getLongValue` on a number flag that isn't a whole number is a type mismatch.
- `getObjectValue` returns a `Value` holding a structure or a list, with numbers as doubles.
- Context values can be strings, booleans, numbers, `Instant`s (compared as instants by `before`/`after` rules), lists and structures.
- `getVariant()` on the details is the variation index; `getFlagMetadata()` has `flagVersion`, `configVersion` and, when a rule matched, `ruleId`.
- `client.onProviderConfigurationChanged(details -> …)` tells you when flags change; `details.getFlagsChanged()` lists them.
- Call `api.shutdown()` on exit to close the stream and send the last experiment events.
- `RailflagOptions.builder()` also takes `stream(false)` (poll only), `pollInterval`, `timeout`, your own `HttpClient`, and `sendEvents(false)` and `eventsInterval` (see Experiments).
- Server keys can read every rule. Keep them on the server; this provider is not for Android apps. Browsers use the JavaScript SDK with a client key.

## Experiments

Start an experiment on a flag in the Railflag dashboard, then record the events it measures with
OpenFeature's `track`:

```java
client.track("purchase", new ImmutableContext("user-42"), new MutableTrackingEventDetails(49.9));
```

```kotlin
client.track("purchase", ImmutableContext("user-42"), MutableTrackingEventDetails(49.9))
```

- Exposures (which variation each user got) are sent automatically for flags in a running experiment; there
  is nothing to call. A user counts once per variation, and only when a percentage rollout picked the
  variation for their targeting key.
- `track` is sent only for events a running experiment counts, and only for a context with a targeting
  key. The value is optional; a missing value counts as 0.
- Both go to your relay every 10 s (`eventsInterval`) in the background, never delaying a flag check, and
  what is left goes on `api.shutdown()`. If the relay can't be reached they are dropped, not retried.
- They carry user keys, only for the experiment's flags and events; Railflag hashes them before storing
  them. `RailflagOptions.builder().sendEvents(false)` turns all of this off.

## Same answers as every other SDK

`Evaluator.java` is a port of `packages/eval`, Railflag's TypeScript evaluator. The tests run it against
the shared test vectors (hashes, buckets and thousands of evaluations generated by the TypeScript
evaluator), so a user lands in the same variation whichever SDK evaluates the flag. Experiment exposures
and `track` events are checked the same way, against `packages/eval/vectors/events-vectors.json`. Context
values follow JavaScript rules: `1` and `true` are different, numbers print as JavaScript prints them, and
strings sort by UTF-16 code units.

Known differences: regexes in `matches` rules run on `java.util.regex`, which reads a few constructs
differently from JavaScript (for example `\d` and `\w` are ASCII-only in both, but character class
subtraction like `[a-z&&[^aeiou]]` only exists in Java), and a date-time without a time zone is read as UTC.

## Development

The source lives in the Railflag monorepo (`packages/sdk-java`).

```sh
./gradlew build                 # also runs the shared evaluation vectors
./gradlew test -PtestJava=11    # the tests on another installed JDK
SY_EMAIL=… SY_PASSWORD=… ./gradlew liveCheck   # end to end against a running Railflag (SY_API, SY_RELAY)
```
